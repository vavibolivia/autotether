# AutoTether

USB로 PC에 연결하면 **USB 테더링을 자동으로 켜고**, **PC별 마지막 테더링 상태를 기억해** 다음 연결 때 그 상태로 맞추도록 안내하는 Android 앱입니다.

- 루트나 Shizuku가 필요 없습니다.
- Android 8.0(API 26) 이상에서 동작하고, Galaxy S23 / Android 16에서 검증했습니다.

## 다운로드

[**Releases**](../../releases/latest) 페이지에서 받습니다.

| 파일 | 용도 |
|---|---|
| `AutoTether-Setup.zip` | **권장.** APK와 PC 설치 스크립트가 들어 있습니다. PC에 아무것도 설치돼 있지 않아도 됩니다. |
| `AutoTether.apk` | 앱만 설치할 때 씁니다. 이후 설정은 앱 안의 "초기 설정" 체크리스트를 따라 하면 됩니다. |

## 설치 (권장: PC 설치 스크립트)

### 0. 폰 준비 (최초 1회, 수동)

adb로 설정하려면 USB 디버깅이 켜져 있어야 해서 이 단계만은 자동화할 수 없습니다.

1. **설정 → 휴대전화 정보 → 소프트웨어 정보 → 빌드번호**를 7번 탭합니다. "개발자 모드가 켜졌습니다"가 표시됩니다.
2. **설정 → 개발자 옵션 → USB 디버깅**을 켭니다.

### 1. PC에서 실행

1. `AutoTether-Setup.zip`의 압축을 풀고 **`설치.bat`**을 더블클릭합니다. 관리자 권한 요청(UAC)에서 **예**를 누릅니다.
2. 폰을 USB로 연결하고, 폰에 뜨는 **"USB 디버깅을 허용하시겠습니까?"**에서 **"이 컴퓨터에서 항상 허용"**을 체크한 뒤 **허용**을 누릅니다.
3. 나머지는 자동으로 진행됩니다.

| 단계 | 내용 |
|---|---|
| PC 방화벽 | USB 테더링으로 연결된 폰이 이 PC의 이름을 조회할 수 있게 규칙을 하나 추가합니다(NetBIOS UDP 137, 유선·로컬 서브넷 한정). |
| adb | PC에 없으면 Google 공식 platform-tools를 내려받습니다. |
| 앱 설치 | `AutoTether.apk`를 설치합니다. |
| 권한 | 알림 허용, 배터리 최적화 제외 |
| 자동 켜기 | 개발자 옵션의 "기본 USB 구성"을 **USB 테더링**으로 설정합니다. |
| 실행 | 앱을 열고 모니터링을 시작합니다. |

진행 로그는 `setup.log`에 남습니다.

> **삼성 폰 참고:** 설정 후 개발자 옵션의 "기본 USB 구성" 화면에는 **"폰 충전만"으로 보일 수 있지만 정상입니다.** 실제 값(`screen_unlocked_functions=RNDIS`)은 테더링으로 저장돼 있습니다. 그 화면에서 다른 항목을 누르면 설정이 바뀔 수 있으니 누르지 마세요. 앱의 "초기 설정" 4번 항목이 ✓인지로 확인하면 됩니다.

### 2. 다른 PC 추가

그 PC에서도 `설치.bat`을 한 번 실행합니다. 폰 설정이 이미 끝났다면 **S** 키를 눌러 **PC 방화벽만** 설정하면 됩니다. 이 설정이 없으면 그 PC는 식별되지 않습니다.

### 폰이 인식되지 않을 때

- 충전 전용이 아닌 **데이터 케이블**인지 확인합니다.
- 폰 알림창에서 USB 모드를 **파일 전송**으로 바꿔 봅니다.
- 삼성 폰은 [Samsung USB 드라이버](https://developer.samsung.com/android-usb-driver)가 필요할 수 있습니다. 설치 스크립트 대기 화면에서 **D** 키를 누르면 페이지가 열립니다.
- 허용 창이 뜨지 않으면 **개발자 옵션 → USB 디버깅 권한 승인 취소**를 누른 뒤 케이블을 다시 꽂습니다.

## 설치 (APK만)

1. `AutoTether.apk`를 폰에서 열어 설치합니다. 출처를 알 수 없는 앱 설치를 허용해야 합니다.
2. 앱을 처음 실행하면 모니터링이 켜지고 알림 권한과 배터리 최적화 제외를 차례로 요청합니다.
3. **초기 설정** 체크리스트에서 ✗나 ? 항목의 버튼을 누르면 해당 설정 항목으로 바로 이동합니다. 예를 들어 "기본 USB 구성" 버튼을 누르면 개발자 옵션의 그 항목이 강조된 채로 열립니다.
4. 각 PC에서는 방화벽 설정을 위해 `설치.bat`을 실행하고 **S** 키를 누릅니다.

## 동작

| 상황 | 동작 |
|---|---|
| 잠금 해제 상태에서 USB 연결 | OS가 테더링을 자동으로 켭니다(기본 USB 구성). |
| 테더링이 켜진 뒤 | PC 이름(호스트명)을 확인하고 PC별로 기록합니다. |
| 마지막에 테더링을 **끈** PC에 연결 | "USB 테더링 끄기" 알림을 띄웁니다. 탭하면 USB 테더링 스위치가 강조된 화면이 열립니다. |
| 자동 켜기를 설정하지 않았고 직전 연결이 ON | "USB 테더링 켜기" 알림을 띄웁니다. |
| USB가 연결된 채 켜기/끄기 | 그 PC의 마지막 상태로 기록합니다. |
| 케이블을 뽑아서 꺼짐 | 사용자가 선택한 것이 아니므로 기록하지 않습니다. |

### 앱이 테더링을 직접 끄지 못하는 이유

USB 테더링 전환에는 시스템 권한(`TETHER_PRIVILEGED`)이 필요합니다. "시스템 설정 변경" 권한으로 요청하는 경로도 있지만, 통신사 테더링 인증이 필요한 폰(예: KT 개통 Galaxy)에서는 거부됩니다(`TETHER_ERROR_NO_CHANGE_TETHERING_PERMISSION`). 그래서 켜기는 OS 기본 USB 구성에 맡기고, 끄기는 알림 한 번 탭과 스위치 한 번 탭으로 처리합니다.

### PC 식별

USB 연결만으로는 상대 PC의 ID를 알 수 없습니다. 그래서 테더링이 켜진 뒤 USB 네트워크 대역에 NetBIOS NBSTAT, mDNS·LLMNR 역조회를 보내 **호스트명**을 얻습니다. PC 쪽 RNDIS MAC은 연결할 때마다 바뀌므로 참고용으로만 표시합니다.

## 되돌리기

- 자동 켜기 해제: **개발자 옵션 → 기본 USB 구성 → 데이터 전송 안 함**
- PC 방화벽 규칙 삭제: 관리자 PowerShell에서 `Remove-NetFirewallRule -Name AutoTether-NetBIOS-In`

## 빌드

```bash
# JDK 17+, Android SDK (local.properties 의 sdk.dir)
./gradlew assembleDebug        # app/build/outputs/apk/debug/app-debug.apk
./gradlew testDebugUnitTest    # 패킷 빌드/파싱 테스트
./gradlew dist                 # dist/AutoTether-Setup/ 과 dist/AutoTether-Setup.zip
```

배포 APK는 debug 키로 서명돼 있습니다. 다른 PC에서 빌드한 APK로 업데이트하면 서명이 달라집니다. 이 경우 설치 스크립트가 기존 앱을 삭제하고 다시 설치하며, 이때 기록이 초기화됩니다.

## 구조

| 파일 | 역할 |
|---|---|
| `TetherMonitorService.kt` | 포그라운드 서비스: USB·테더링 상태 추적, 세션·디바운스, 알림 |
| `PcIdentifier.kt` | NBSTAT / mDNS / LLMNR 질의·파싱 |
| `TetherProbe.kt` | 테더 인터페이스 감지, 설정 화면 바로가기(항목 강조) |
| `HistoryStore.kt` | PC별 기록, 직전 세션 |
| `MainActivity.kt` | 상태, 초기 설정 체크리스트, PC 기록 |
| `BootReceiver.kt` | 부팅 후 자동 시작, 설정값 |
| `setup/setup.ps1`, `setup/설치.bat` | PC 설치·설정 스크립트 |

로그 보기: `adb logcat -s AutoTether PcIdentifier`

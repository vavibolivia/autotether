# 2026-11-05 AutoTether 작업 기록

## 목표

특정 PC에 USB를 꽂으면 그 PC에서의 USB 테더링 사용 기록을 저장하고, 마지막 상태에 따라 테더링을 자동으로 켜거나 끄는 Android 앱을 만든다.

## 결과 요약

| 항목 | 상태 |
|---|---|
| 앱 (`kr.across.autotether`) | v1.0.2, GitHub Releases 배포 |
| PC 설치 스크립트 (`설치.bat` / `setup.ps1`) | 아무것도 없는 PC 기준으로 설치·설정 자동화 |
| 실기기 검증 | Galaxy S23 (SM-S911N), Android 16 (API 36), KT |
| 저장소 | https://github.com/vavibolivia/autotether (공개), JH2305 write 권한 초대 |

## 설계 결정과 근거

### 1. 테더링 전환 방식: 권한 없이 OS "기본 USB 구성"에 맡김

- 일반 앱은 `TETHER_PRIVILEGED`(시스템 권한)가 없어 테더링을 직접 바꿀 수 없다.
- **시도:** "시스템 설정 변경" 권한으로 hidden API인 `TetheringManager.setUsbTethering` / `startTethering`을 호출했다.
  - 실기기에서 `SecurityException`과 `startTethering error=14`(`TETHER_ERROR_NO_CHANGE_TETHERING_PERMISSION`)로 거부됐다.
  - 통신사 테더링 인증이 필요한 폰에서는 이 경로가 막힌다. 해당 코드는 제거했다.
- **채택:** adb shell 권한으로 `svc usb setScreenUnlockedFunctions rndis`를 설정했다. 개발자 옵션의 "기본 USB 구성 = USB 테더링"과 같은 설정이다.
  - 잠금 해제 상태에서 연결하면 OS가 테더링을 켠다.
  - 끄기는 알림 탭 → USB 테더링 스위치가 강조된 화면 → 스위치 탭으로 처리한다.

### 2. PC 식별: MAC이 아니라 호스트명

- USB 연결만으로는 상대 PC의 ID를 알 수 없다. 테더링이 켜진 뒤 USB 네트워크 대역(/24)에 아래 질의를 보낸다.
  - NetBIOS NBSTAT (UDP 137)
  - mDNS 역방향 PTR (UDP 5353)
  - LLMNR 역방향 PTR (UDP 5355)
- **실측:** PC 쪽 RNDIS MAC은 연결할 때마다 바뀌었다(예: 9A:09…, AE:65…, D6:60…, 5E:B0…). 폰의 USB 가젯이 정하는 값이라 **키로 쓸 수 없다**. 그래서 호스트명을 키로 쓰고, MAC은 참고용으로만 표시한다.
- **실측:** Windows는 USB 테더링 네트워크를 **Public**으로 잡는다. 기본 방화벽은 Public에서 NetBIOS 수신을 막고, mDNS 역조회에도 응답하지 않았다. 그래서 첫 시도는 식별에 실패했다.
- **해결:** 설치 스크립트가 방화벽 규칙 `AutoTether-NetBIOS-In`을 추가한다(UDP 137, 유선 인터페이스, 로컬 서브넷, 모든 프로필). 추가한 뒤 NetBIOS로 식별에 성공했다.
  - 네트워크 프로필을 Private로 바꾸는 방법은 연결마다 새 네트워크로 인식될 수 있어서 쓰지 않았다.

### 3. 세션·기록 규칙

- USB가 연결된 채 테더링을 켜거나 끄면 그 PC의 마지막 상태로 기록한다.
- 케이블을 뽑아서 테더링이 꺼진 것은 사용자가 선택한 것이 아니므로 기록하지 않는다.
- USB 기능 전환(MTP↔RNDIS) 중 잠깐 끊기는 `USB_STATE`는 3초 디바운스로 무시한다. 테더링 OFF 기록은 4초 지연 후 확정한다.
- 마지막에 OFF였던 PC에서 테더링이 연결 직후 저절로 켜지면 "끄기" 알림을 띄운다.
- 자동 켜기를 설정하지 않았고 직전 세션이 ON이면 "켜기" 알림을 띄운다.

### 설정 화면 바로가기 (한 번에 설정)

`:settings:fragment_args_key` extra를 넘기면 Settings가 해당 항목까지 스크롤하고 강조한다. 실기기에서 확인한 경로는 다음과 같다.

| 버튼/알림 | 이동 위치 |
|---|---|
| 테더링 켜기/끄기 알림, "테더링 설정" | `Settings$SecTetherSettingsActivity`(삼성) → USB 테더링 스위치가 첫 화면에 표시 |
| 4번 "기본 USB 구성" | 개발자 옵션 → "기본 USB 구성" 항목 강조 |
| 2번 배터리 | `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` 시스템 대화상자 |
| 1번 알림 | 런타임 권한 대화상자, 이미 거부했다면 앱 알림 설정 화면 |

### PC 설치 스크립트 (환경이 없는 PC 기준)

1. 관리자 권한으로 다시 실행(UAC)
2. 방화벽 규칙 추가. USB 테더링 어댑터의 NetBIOS가 꺼져 있으면 켠다.
3. adb가 없으면 Google 공식 `platform-tools-latest-windows.zip`을 내려받는다.
4. 폰 연결 대기
   - 연결 상태(none / unauthorized / offline / multi)별로 안내한다.
   - S 키는 폰 설정을 건너뛰고(PC만 설정), D 키는 삼성 USB 드라이버 페이지를 연다.
5. APK 설치. 서명이 다르면 삭제 후 다시 설치한다.
6. 알림 권한 허용, 배터리 최적화 제외(`deviceidle whitelist`), 기본 USB 구성 = rndis(실패하면 ncm)
7. 앱 실행. 기본 USB 구성 설정에 성공했다는 사실을 앱에 전달한다. 앱은 이 값을 직접 읽을 권한이 없다.

PowerShell 5.1 대응:
- UTF-8 BOM으로 저장(한글)
- `ErrorActionPreference=Continue`(adb의 stderr 출력이 오류로 처리되는 문제 회피)
- `trap`으로 오류가 나도 창이 바로 닫히지 않게 함
- 로그는 `setup.log`에 남김

## USB 디버깅 허용 단계 자동 복구 (main 반영, 미릴리스)

- **배경:** 오늘 폰에서 "허용"을 눌렀는데도 `unauthorized`가 풀리지 않았고, 수동으로 `adb reconnect`를 실행해 해결했다. 이 단계가 막히면 설치 전체가 진행되지 않는다.
- **변경 (`setup.ps1`):** `unauthorized`/`offline` 상태가 10초 이상 이어지면 아래 순서로 자동 복구한다.
  1. 10초 간격으로 `adb reconnect`를 3회 시도
  2. 그래도 안 되면 adb 서버를 재시작해 허용 창이 다시 뜨게 함
  3. 그래도 안 되면 "USB 디버깅 권한 승인 취소 → 케이블 다시 연결"을 안내하고 처음부터 반복
- **시험:** adb 키를 새로 만들어(기존 키는 `~/.android/adbkey*.bak-20261105`로 백업) 처음 연결하는 PC 상황을 재현했다.
  - 결과: `unauthorized` → 재연결 1회 시도 → **폰이 adb 목록에서 사라짐(none)** → 사용자가 S로 건너뜀.
  - 현재 폰은 새 키로 `device`(허용됨) 상태다.
- **판단:** `adb reconnect`는 허용 대기 중인 폰을 목록에서 사라지게 할 수 있다. 오전 수동 조치 때도 reconnect 직후 사라졌다가 케이블을 다시 꽂자 정상화됐다. **자동 복구가 실제로 해결해 준다는 것은 검증되지 않았다.**
  - 다음 작업: 허용 대기 중(unauthorized)에는 reconnect 대신 adb 서버 재시작만 쓰거나, 재연결 후 none이 되면 "케이블 다시 연결" 안내를 바로 띄우도록 조정하고 재시험한다.
  - 그전까지 릴리스 zip(v1.0.2)에는 이 변경이 들어가지 않는다.

## 남은 확인 사항

1. **케이블을 뽑았다가 다시 꽂는 시험:** 잠금 해제 상태에서 테더링이 자동으로 켜지는지. adb로 "충전만"으로 바꾼 시험에서는 자동 복귀가 일어나지 않았다. 설정은 잠금 해제나 재연결 시점에 적용되므로 실제 재연결 확인이 필요하다.
2. **OFF로 기록된 PC에 재연결:** "USB 테더링 끄기" 알림이 뜨는지.
3. **폰 재부팅 후 모니터링 자동 시작**
4. **다른 PC에서의 식별:** 방화벽 스크립트를 적용한 두 번째 PC.
5. **장시간 백그라운드 유지:** 삼성 절전 정책으로 서비스가 종료되지 않는지.
6. **USB 디버깅 허용 자동 복구:** 위 판단대로 조정하고 재시험한다.
7. **배포 APK 서명:** 이 PC의 debug 키로 서명돼 있다. 다른 PC에서 빌드하면 서명이 달라져 업데이트할 때 삭제 후 다시 설치(기록 초기화)가 필요하다. release 키 도입을 검토한다.
